# 2026-09-10

## 修复 Vercel 构建报错 `unmatched-function-pattern`（api/**/*.go）

- 根因：项目被判定为 Go Framework Preset。`packages/frameworks/src/frameworks.ts` 中
  go 的定义带 `ignoreRuntimes: ['@vercel/go']`，一旦 framework=go，
  `detect-builders.ts` 里 `api/**/!(*_test).go → @vercel/go` 这条匹配被整体过滤掉，
  api/ 下的文件不再识别为 Serverless Function，于是 `functions` 的 key 一个都匹配不上。
- 改动：`vercel.json` 加 `"framework": null`；README 第三节修正「Framework Preset 选 Go 或 Other」
  （选 Go 必炸），新增「方式三 Go Framework Preset」与排查表。
- 结论（项目铁律）：本仓库必须 `framework: null` + api 目录函数模式；
  若改用服务器模式，入口只能是 main.go / cmd/api/main.go / cmd/server/main.go，且必须删掉 functions 段。
- 本地 `go build ./...` + `go vet ./...` 通过。

## 落地服务器模式（双模式共存重构）
- 业务 handler 全部抽到 `internal/handlers`（Index/Health/Hello/Echo/Config），
  `api/<name>/index.go` 退化成一行转发 `func Handler(w,r){ handlers.Xxx(w,r) }`。
- 新增 `cmd/api/main.go`：ServeMux 注册 5 个路由 + `site.Handler` 托管首页，监听 `PORT`。
- 新增根包 `site.go`（package site，导入路径就是 `vercel-go-demo`）：`//go:embed public/index.html`。
  放根目录是因为 embed 不能引用父目录，只有根包能 embed 到 public/。
- 新增 `vercel.server.json`（framework: go，无 functions 段），切换命令
  `vercel deploy --local-config vercel.server.json`。
- 实测：cmd/api 五接口 + 首页 200 + 未知路径 404 全部通过；devserver（函数模式）回归通过。
- 坑：测试用的 apisrv.exe 被后台进程占用，rm/mv 被 safe-delete 拦；
  解法 `MSYS_NO_PATHCONV=1 taskkill /F /IM xxx.exe` 再 `node -e "fs.unlinkSync(...)"`。

## 修复 `use of internal package ... not allowed`
- 症状：Vercel 函数模式构建报 `imports handler/api/config` +
  `index.go:6:2: use of internal package vercel-go-demo/internal/config not allowed`。
- 根因：Vercel 构建 api 下函数时生成 `main__vc__go__.go` 并**改写模块路径**
  （`vercel-go-demo` → 包名 `handler`），internal 包相对它变成外部模块被拒。
  本地 `go build ./...` 完全发现不了，只有 Vercel 上炸。
- 修法：`internal/` 整个改名 `pkg/`，import 全量 `vercel-go-demo/internal/...` → `.../pkg/...`
  （11 个 go 文件）。备选：公开桥接包 或 直接走服务器模式。
- 项目约定修正：**共享代码不能放 internal/**，README 新增第八节专门讲这个坑。
- 回归：cmd/api（服务器模式）五接口 + 首页 200 + 404 通过；devserver（函数模式）通过。
